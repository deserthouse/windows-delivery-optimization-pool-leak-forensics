# 01 · 因果链：四环证据

**简体中文** · [English](01-the-chain.en.md)

每一环都先给现象、再给实测、最后给"为什么它能成立"。全部数字为排查会话（2026-09-21/22）的重复测量稳定值，转录说明见 README 证据纪律节。

---

## 第一环：卡死的做种任务

**现象**：`Get-DeliveryOptimizationStatus` 显示 3 个下载任务，全部状态 `Paused`，每个挂着 250~299 个互联网 peer，下载字节几乎为零但上传字节在涨。

关键任务全字段（节选，完整见 `evidence/do-jobs-before.txt`）：

```
FileId        : bca53c4f…（22.8 MB 的 Windows 更新包）
Status        : Paused
TotalBytesDownloaded : 793,779      ← 3.5%
BytesFromHttp : 793,779
InternetConnectionCount : 258
BytesToInternetPeers   : 4,427,647  ← 已向陌生 peer 上传 4.4 MB
DownloadMode  : Internet
Caller        : WU Client Download
```

**为什么成立**：任务卡在 Paused 后不会自行清除（挂到过期日），但 peer 连接与上传继续维持——你的机器在给全世界分发一个自己只下了 3.5% 的更新片段。每个连接都需要持续的流量统计。

**为什么清缓存/重启没用**：做种会话持久化在 DO 的状态库里，不是缓存文件，也不随重启消失（实测：重启后同 FileId 任务原样回来）。

## 第二环：WMI 配额死循环

**现象**：WMI-Activity 操作日志 400 条近期记录中，**209 条来自 DoSvc**（第二名 36 条），全部是同一个查询、全部失败：

```
SELECT * FROM MSFT_NetAdapterStatisticsSettingData
WHERE Name = 'Realtek Gaming 2.5GbE Family Controller'
ResultCode = 0x80041032   ← WMI 配额耗尽
```

**为什么成立**：800+ 连接 × 流量统计需求 → 每秒上千次网卡计数器查询；WMI 每账户配额被吃满后查询全部被拒；DoSvc 的重试逻辑没有退避（失败→立即重试），形成死循环。每轮重试的完整路径——COM 激活、WMI 服务、短命提供者进程、驱动读计数器——全部白跑，但每个环节都在内核里创建又销毁对象。

---

## 第三环：VAD 泄漏

**现象**：非分页池 5 天涨至 4,138 MB；池标签审计定位到 `VadS`（内核虚拟地址描述符短节点）：1,478 MB / **1,615 万个存活节点**；另有 `daV` 族 688 MB。处置后重启回落 975 MB。

**为什么成立**：第二环的高频生灭流水线（每秒上千次对象创建销毁）上存在回收缺口——8.4 亿次分配对 8.35 亿次释放，差值以每秒 50~200 个节点的速度净增。三个铁证：

1. **不属于任何用户进程**：按进程枚举虚拟内存区域，全机总和 <40 万区域，对不上 1,600 万节点；
2. **泄漏速率波动与系统活动同步**：CPU 繁忙（如构建任务满载）时泄漏几乎停止，空闲时全速——典型的低优先级后台行为；
3. **逐服务停用对照**：停 Intel SUR / 联想 Vantage / NVIDIA 容器后泄漏照旧；**停 DoSvc 后速率从峰值 17,410/90 秒骤降**——定案的关键实验。

---

## 第四环：整机冻结

**现象**：非分页池是 GPU 驱动（DMA 缓冲）、网络栈、磁盘 IO 的必需内存；池子被 4.1 GB 废节点占满后，高需求场景（游戏加载、大流量）越过临界点 → 分配阻塞 → 渲染停摆 → 桌面合成器跟着等 GPU → 全屏冻结。数十秒后内存管理器腾出碎片空间，自愈——不留崩溃记录。

**游戏卡死的完整现场**（玩家视角的同一案件）：冻结总在游戏时发作（需求峰值撞上水位线）、卡数十秒自愈（脉冲回落）、日志几乎无痕（错误报告服务自己也在冻结名单里）。本机时间线上有可对照的现场：游戏结束 8 分钟后外壳崩溃、任务管理器冻死、一次反作弊驱动绿屏（成因未定——内存枯竭诱发与该驱动自身缺陷两个假说并存，未逐一排除）。

---

## 为什么修复是"关 P2P"

链条的燃料是 peer 连接——没有 peer 就没有流量统计需求，死循环物理上无法维持。所以：

- 不需要动任何驱动（本案驱动全部无罪）；
- 不需要禁用 DoSvc 服务（Windows 更新依赖它，禁用得不偿失）；
- 只需要把 P2P 模式关到"仅 HTTP"，做种队列即被清空。

具体步骤见 [02 修复](02-remediation.md)。
